Why this exists

Useful memory without hand-waving.

LLM-assisted research is most valuable when organisation gets easier without blurring the line between evidence, synthesis and memory. llm-wiki gives OpenClaw a disciplined place to put what you know — and what you do not.

⌁

Sources stay sources

Raw evidence is immutable. A later summary can change; the ingested material it was based on does not silently mutate underneath you.

↗

Provenance stays visible

Compiled knowledge is linked back to source material, so an answer can be inspected rather than merely accepted.

∅

Gaps are first-class

If the selected wiki does not contain the evidence, the skill is instructed to say so instead of filling the hole with model memory.

◎

Queries stay bounded

Indexes are read first and the smallest relevant workflow is preferred, making everyday retrieval cheaper and more predictable.

⇄

Research can fan out

Independent child agents can search in parallel while a single parent agent remains responsible for credibility, deduplication and wiki writes.

◫

Topics stay separate

Different projects or domains can coexist without being silently merged. Cross-topic work happens only when you ask for it.

If you are new to this

Think “research notebook that can organise itself”.

You do not need to design a database. Start a wiki, give OpenClaw material to ingest, then ask it to compile and query what has accumulated.

  • Keep project sources in one discoverable place
  • Ask natural-language questions over accumulated material
  • Separate original evidence from generated synthesis
  • Use the read-only query mode when you just want answers
If you are doing research

Think “evidence layer + synthesis layer + operational layer”.

The design distinguishes source evidence, compiled claims, inventory state and session memory. That distinction matters when you need traceability rather than a convenient pile of generated notes.

  • Preserve raw evidence and source metadata
  • Audit provenance, stale indexes and synthesis quality
  • Track datasets, candidate sources, ideas and outputs separately
  • Run multi-agent discovery without concurrent writes to the knowledge state
How it works

A small pipeline with clear boundaries.

The knowledge model is deliberately boring in the best way: Markdown, YAML frontmatter, derived indexes and explicit file roles. The intelligence is in the workflow, not a proprietary database.

1

Ingest

Add a report, article, paper, note, URL or collection.

2

Preserve

Store the source as immutable raw evidence with provenance.

3

Compile

Build synthesis that integrates sources and distinguishes disagreement.

4

Query / research

Use bounded retrieval or fan out discovery across independent agents.

5

Output

Create reusable evidence-backed answers, briefs and project artefacts.

Two modes

Write when you mean to. Read safely when you do not.

The package ships with a full manager and an explicit read-only query profile. That lets you use the same knowledge hub for active research and low-risk retrieval.

Research mode

Parallel discovery. One accountable writer.

OpenClaw sub-agents can explore different research lenses concurrently. They return evidence bundles; the parent agent cross-checks, deduplicates, assesses credibility and decides what is actually written to the wiki.

Scale the search, not the chaos.

Fan-out targets are deliberately bounded. If the runtime child limit is lower, the work proceeds in waves rather than demanding a global configuration change.

Standard
up to 5
Deep
up to 8
Exhaustive
up to 10
01
Children discover; they do not write.

Research agents search, fetch, read and analyse independently, reducing same-file races and self-promotion of findings.

02
Evidence bundles are structured.

Useful sources return title, URL, date/type, key claims, relevance, provisional quality, uncertainty and suggested ingestion reason.

03
The parent reassesses credibility.

Final source selection and credibility are coordinator responsibilities, not delegated facts.

04
Session memory is not evidence.

Operational memory remains separate until a user explicitly promotes it into a topic.

05
Mutation is logged.

Writes append operational history rather than rewriting it, preserving a trail of changes to knowledge state.

Get started

Clone it. Install it. Give your next project a memory.

The adapter is deliberately thin: llm-wiki remains the knowledge model; this package maps that model onto OpenClaw’s skill, filesystem, web and sub-agent capabilities.

git clone https://github.com/staffordlumsden/llm-wiki-openclaw.git && openclaw skills install ./llm-wiki-openclaw --as llm-wiki
/llm-wiki initialise a local wiki for this project
/llm-wiki ingest https://example.org/report into administrative-law
/llm-wiki research automated legal citation checking --deep
/wiki-query what does this corpus say about oral assessment reliability?
